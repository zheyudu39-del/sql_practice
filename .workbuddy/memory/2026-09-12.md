## 追加答疑（20:12）：讲解 GROUP BY（脚本 B5）
- 用户贴出 `SELECT category, COUNT(*) AS 商品数, ROUND(AVG(price),2) AS 平均价 FROM products GROUP BY category;` 求解。
- 讲解要点：GROUP BY = 按 category 把 8 行压成 4 组，每组输出一行；COUNT(*) 计组内行数，AVG(price) 求组内均价，ROUND 保留 2 位。
- 预期结果（未跑 G2 涨价时）：手机 2/6249.00、电脑 2/7149.00、配件 2/899.00、家居 2/2249.00；**若已跑 G2**（配件涨价 10%），配件平均价变为 988.90。
- 两条关键提醒（MariaDB 特性）：
  1. **SELECT 里只能出现分组列或聚合函数**。MariaDB 默认**未**开启 `ONLY_FULL_GROUP_BY`，所以写 `SELECT name, category, COUNT(*) ... GROUP BY category` 不会报错，而是**静默返回组内任意一行的 name** —— 隐藏的坑。
  2. 没写 ORDER BY 时，分组结果的顺序**不做保证**。
- 教学方式：用「8 行 → 4 组」的分组示意图解释，效果直观。

## 追加答疑（22:53）：`UPDATE ... SET score = score + 2` 为什么"没生效"
- 用户问 `score = score + 2` 的含义，以及为什么成绩没加 2。
- 讲解要点：
  - `=` 是**赋值**不是数学等号；右边 `score` 是该行**旧值**；MariaDB **逐行**处理（读旧值→+2→写回），每行各算各的，不是共用同一个值。
  - 对比 `SET score = 2`（全部变成 2）vs `SET score = score + 2`（各自累加）。
- 「没生效」的三大原因（已给出诊断命令）：
  1. **WHERE 匹配 0 行** —— 看 UPDATE 返回的 `Query OK, N rows affected`，N=0 就是没匹配到（无数据 / 班级名不一致）
  2. **score 是 NULL** —— `NULL + 2 = NULL`，看起来"没变"。这正是给 score 加 `DEFAULT 0` 的原因
  3. **在看 UPDATE 之前那次 SELECT 的旧输出** —— 控制台不会自动刷新
- 万能诊断三步：`SELECT DATABASE();` / `SELECT COUNT(*) FROM students;` / `SELECT * FROM students WHERE class_name = '一班';`

## 追加答疑（22:54）：真相是"验证条件 ≠ 修改条件"
- 上一轮的疑问有了实锤：用户的 `UPDATE students SET score=score+2 WHERE class_name='一班';` **执行成功**（`Rows matched: 2  Changed: 2`），但他接着用 `WHERE name='刘强'` 去验证，看到 60.00 没变就以为失败。
- **根本原因**：刘强是**二班**的，从来不在"一班"的 WHERE 范围内。他 SELECT 验证用的是 `name='刘强'`，UPDATE 改的是 `class_name='一班'` —— **两步的筛选条件不是同一个**。
- 可复用教学要点（以后遇到"改了没反应"先问这句）：
  - **验证用的 SELECT，必须和 UPDATE 的 WHERE 用同一个条件**，否则永远验证不到（或验证错）。
  - `Rows matched` = WHERE 匹配到的行数；`Changed` = 值真正发生变化的行数。值本来就等于新值时会 matched>0 而 Changed=0。
